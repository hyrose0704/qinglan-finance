# 云端资金档案

GitHub Pages 只发布网页，不运行数据库。资产存放在独立的 Supabase PostgreSQL 数据库，网页重新发布不会重建或清空它。尚未配置数据库时，界面明确显示“云数据库尚未连接”，只保存浏览器副本；这不等于云端已经上线。

## 部署一次，之后无需随网页重建

1. 在自己的 Supabase 组织中选择免费项目，确认管理台显示的方案和费用。项目健康就绪后再运行迁移。既有项目先检查表与迁移记录，避免重复执行。
2. 用迁移工具应用 `supabase/migrations/202611200001_asset_profiles.sql`。保存后不要修改已应用的迁移；后续变更追加新文件。它只创建本应用的两张表、读取策略和保存函数，不插入个人档案或演示资产。
3. 将项目的 HTTPS URL 与 **publishable Key** 写入 `public/data/cloud-config.json` 的 `url`、`publishableKey`。这是公开客户端配置，不是数据库管理密码。也可在网站“个人中心 → 管理员”先配置当前浏览器。严禁填写 `sb_secret_`、`service_role` 或数据库连接密码。
4. 保留邮箱验证。在 Supabase 的 Authentication → URL Configuration 中，将 Site URL 设为当前公开站点的完整地址 `https://hyrose0704.github.io/qinglan-finance/`，并将该地址列入允许的 Redirect URLs。注册会请求回到此地址。确认邮件默认在注册浏览器使用 PKCE 完成登录，在其他设备打开邮件后，可用邮箱密码登录。Supabase 内置发信服务通常仅允许发送给项目团队邮箱。向其他人开放自助注册前，请配置自己的 SMTP 并验证投递。少量账号也可由管理员在 Authentication → Users 中创建已确认的账号，向本人单独交付凭据。
5. 构建、测试后同步 GitHub，等待 Pages 部署成功。首次使用者在“个人中心”注册并确认邮箱，然后登录资金档案。网站不会代建普通用户密码。
6. 原浏览器档案独立保留。登录空账号后，点击“查看并迁移原有档案”，核对账号与全部金额，再确认保存。云端已有档案时优先读取云端，不自动用旧浏览器金额覆盖。

## 保存与恢复

- 新建/编辑资产、修改风险偏好或导入档案时，先写当前账号的浏览器副本，再请求云端保存；只有云端响应成功才显示云端已保存及版本号。
- 浏览器缓存按项目与用户编号分开；稳定旧键 `qinglan-profile-v1` 继续用于未登录的原档案。每个缓存保留10份近期副本，主记录损坏或缺失时可恢复。所有浏览器副本都可能被清理网站数据删除，不能替代云端。
- 断网或保存失败时保留待同步内容。重新读取云端后，同一基线的内容等待用户点击同步；另一台设备已经更新则显示差异，不自动覆盖。网络响应丢失而数据库其实保存成功时，通过内容比较识别已提交内容。
- 云端保存使用事务与账号级锁、预期版本和预期账号检查；两台设备同时保存仅允许匹配基线的一次更新。即使浏览器账号在请求期间改变，也不能把前一个账号的资产写给后一个账号。
- 数据库保留每个账号最近20次保存，恢复旧版时另建新版本。它是有限历史，不是无限期备份；定期导出重要档案。
- 普通网页部署只构建静态文件，不执行建表、清空或资产导入。数据库迁移需要独立显式操作。

## 权限与范围

两张表启用 RLS。匿名用户没有表读取、写入或保存函数执行权限；已登录用户仅可读取 `auth.uid()` 对应的记录。直接写表没有权限，保存只经过固定搜索路径的函数，逐项校验字段、账号与版本，不接收客户端指定的所有者。

资产对象只包括收支、持仓、预留、手动价格、估值开关、风险偏好与填写标记。不上传 AI Key、OpenAI 授权、助手背景/对话、学习进度或规划问卷。登录会话由 Supabase 官方客户端管理并保留在当前浏览器；密码不持久化到应用。浏览器本地副本并非加密保险箱，共用电脑请退出账号并留意设备隐私。

本项目不承诺第三方免费方案永久不变。免费项目可能受存储、活跃度、邮件和请求额度限制或暂停，状态以 [Supabase 管理台](https://supabase.com/dashboard) 和 [定价说明](https://supabase.com/pricing) 为准。暂停或连接失败时网页保留本机副本并显示未同步，不伪装为云端保存成功。

## 验证

`npm test` 在隔离的 PGlite PostgreSQL 中执行原始 SQL 迁移，验证匿名拒绝、双账号隔离、账号切换保护、过期版本拒绝、非法输入、20版保留及关闭数据库后重开恢复；不会连接生产数据库或上传真实资产。另有旧档案迁移、存储部分失败、主记录损坏和离线冲突测试。`npm run build` 校验 TypeScript 与生产构建。

生产验收须另外在已配置的服务中完成邮箱登录、保存、刷新和另一设备读取。未接通 Supabase 账号时，本地测试通过不能证明生产云端已部署。
